# 05 — 技术选型

## 1. 技术栈总览

| 类别 | 选型 | 理由 |
|------|------|------|
| 语言 | Python 3.11+ | 生态成熟、量化库丰富 |
| 包管理 | `uv` 或 `poetry` | 锁定依赖、可复现构建 |
| 爬取 | AkShare（MVP） | A 股数据免费、社区活跃 |
| HTTP | `httpx` / `aiohttp` | 异步友好 |
| 数据处理 | `pandas`, `numpy` | 指标计算标准方案 |
| 预测 | 阶段 A：自研基线 + `statsmodels`；阶段 B：PyTorch（可选） | 先可解释后深度学习 |
| 可视化 | `plotly` | 交互图 + HTML 导出 |
| API | `FastAPI` | 类型友好、OpenAPI 自动生成 |
| CLI | `typer` | 与 FastAPI 同属现代 Python CLI |
| 配置 | `pydantic-settings` | 校验 + 环境变量 |
| 存储 | SQLite → PostgreSQL | MVP 零运维，生产可切换 |
| 缓存/限流 | 内存 → Redis | 渐进增强 |
| 测试 | `pytest`, `pytest-asyncio`, `pytest-cov` | TDD 标配 |
| 质量 | `ruff`, `mypy` | lint + 类型检查 |

## 2. 关键取舍

### 2.1 AkShare vs 自建爬虫

- **选 AkShare**：降低合规与维护成本，MVP 快速验证
- **风险**：上游接口变更 → 通过 `IQuoteSource` 适配器隔离，预留第二数据源

### 2.2 asyncio vs 多线程

- **默认 asyncio**：适合 I/O 密集爬取
- **CPU 指标**：在 sync 函数中向量化，或用进程池 offload

### 2.3 预测模型路线（已确认：基线 → 深度学习）

| 阶段 | 里程碑 | 模型 | 依赖组 |
|------|--------|------|--------|
| **A** | M3 MVP | MA 外推、线性回归 | 核心包 |
| **A** | M3 扩展 | Holt-Winters、ARIMA | `statsmodels`（可选） |
| **B** | M5+ | LSTM、Transformer | `pip install .[ml]` |

详见 [07-预测路线图.md](./07-预测路线图.md)。阶段 B 不阻塞 MVP 发布。
